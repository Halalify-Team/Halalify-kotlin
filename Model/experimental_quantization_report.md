# Experimental weight quantization report

The original backup was used as the source:

- `halalify_gender_v3_float32.original.backup.tflite`
- SHA-256: `8F03A7F817C4604FFB8E29C5E2ECE70F4AE8A1BB2C2D189C11E9DD82DEF7E07A`

The experimental model is:

- `halalify_gender_v3_experimental_int8_weights.tflite`
- convolution weights stored as symmetric per-tensor INT8
- Float32 `DEQUANTIZE` nodes inserted before the convolution consumers
- input/output remain Float32, so the app's current tensor contract is preserved

The model loaded and allocated successfully in TensorFlow Lite with input
`float32 [1, 416, 416, 3]` and output `float32 [1, 7, 3549]`.

## Comparison sample

The comparison used the 10 JPEG files in `../test-data/coco-sample`. Each image
was decoded, letterboxed to `416x416` with RGB padding `(114, 114, 114)`,
normalized to `[0, 1]`, and passed through both models with one interpreter
thread. The original model was treated as the reference; this is not a
ground-truth accuracy evaluation.

| Metric | Result |
|---|---:|
| Images | 10 |
| Mean absolute raw-output difference | 0.7039 |
| Maximum absolute raw-output difference | 110.9230 |
| Mean candidate-count delta at score 0.25 | 0.0 |
| Candidate class match rate vs original | 98.59% |

The experimental file is not installed into the Android app. It is a
Float32-compatible proxy for quantization-error testing; because the inserted
dequantization keeps the convolution path Float32, it should not be assumed to
provide the battery reduction of a fully integer-quantized model.

## Full INT8 attempt

Using TensorFlow Lite's internal calibrator and the same 10 images produced
`halalify_gender_v3_full_int8_experimental.tflite` at `3,292,832` bytes. It
loaded successfully with `int8` input and `int8` output, but the quality check
was not acceptable:

- Mean absolute dequantized output difference: `5.7276`
- Candidate-count delta at score `0.25`: `-7.1` per image
- Candidate class match rate vs the Float32 reference: `0%`

Keeping Float32 I/O while quantizing the internal graph produced essentially
the same result. The full INT8 artifacts are therefore retained for research
only and are not wired into the app. The output tensor combines box coordinates
and class scores, so a single per-tensor INT8 output scale loses too much
precision in the scores. A production-quality full INT8 export requires the
original graph (or retraining/QAT) and a quantization-aware export strategy.

## Repaired production export

The production export is:

- `halalify_gender_v3_full_int8.tflite`
- SHA-256: `65E2B0BE46BC7E865EEDD2E084E6FC8CCB4258C81213A3EBE1D8333218A503B0`
- size: `3,292,400` bytes
- internal weights and activations: INT8
- input: INT8 `[1,416,416,3]`
- outputs: INT8 `[1,4,3549]` and INT8 `[1,3,3549]`

It was generated by `training/quantize_split_output_tflite.py`. During
calibration the final box branch `[1,4,3549]` and confidence branch
`[1,3,3549]` are exposed as separate INT8 outputs. The native adapter
dequantizes each branch with its own scale before reconstructing the legacy
Float32 `[1,7,3549]` buffer.

On the same 10-image comparison set, versus the original Float32 model:

| Metric | Repaired result |
|---|---:|
| Mean absolute raw-output difference | 3.9743 |
| Mean absolute coordinate difference | 6.9549 |
| Mean absolute confidence difference | 0.0001143 |
| Final detections after threshold/NMS | 9 original / 9 INT8 |
| Class match among common score-qualified candidates | 100% |
| Final detections matched at IoU >= 0.5 | 8 / 9 |

This is a raw-output regression against the original model, not a ground-truth
accuracy evaluation. The original Float32 and backup files were not modified.

## Expanded comparison: 190 images

The direct comparison between `halalify_gender_v3_float32.tflite` and
`halalify_gender_v3_split_output_int8.tflite` was repeated on all 190 JPEGs in
`test-data`: the original 60 samples, 128 COCO128 images, and 2 successfully
downloaded Wikimedia samples. COCO128 is the public 128-image COCO sample
published by Ultralytics.

| Metric | Result |
|---|---:|
| Images | 190 |
| Mean absolute raw-output difference | 3.445942 |
| Maximum absolute raw-output difference | 271.723267 |
| Mean absolute confidence difference | 0.00008651 |
| Original / INT8 final detections | 122 / 114 |
| Mean final-detection count delta | -0.0421 |
| Common candidate class match | 99.97% |
| Final detections matched at IoU >= 0.5 | 110 / 122 |
| Images with any count or box difference | 15 / 190 |

This larger set confirms that the two models are not numerically identical,
but their class decisions remain highly consistent. The remaining differences
are mostly confidence-threshold/NMS boundary cases and box-coordinate changes;
this is still a regression comparison, not a ground-truth accuracy test.
